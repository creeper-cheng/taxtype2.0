# 税格 TAXTYPE · 运行说明

## 怎么跑

**双击 `index.html` 即可**，用浏览器打开。

- 单文件，零依赖，零构建，零联网
- 不需要服务器、不需要 npm、不需要任何外部资源
- 全程本地计算，不上传任何数据

想部署的话，把 `index.html` 扔进任意静态托管（GitHub Pages / Vercel / 对象存储）即可，分享链接功能需要 http(s) 协议才能跨设备生效。

## 玩什么

20 道题 → 四字母纳税人格。

| 维度 | 字母 | 含义 |
|---|---|---|
| 认知度 | **K** / U | 政策门儿清 ↔ 一知半解 |
| 主动性 | **A** / P | 主动出击 ↔ 随缘摆烂 |
| 筹划倾向 | **O** / D | 精打细算 ↔ 不折腾 |
| 情绪反应 | **W** / C | 一提到税就慌 ↔ 淡定 |

- **5 道知识题**有标准答案，答完立刻显示解析 + 政策文号
- **15 道情景题**测倾向（主动性 / 筹划倾向 / 情绪反应各 5 道），其中 8 道带科普彩蛋
- 落在 45–55 区间的维度标为**边界型**，不强行贴标签
- 结果页含：四维剖面 / 正经解读 / 隐藏福利（可能漏领的钱）/ 答错回顾 / 风险提示 / 三条行动清单 / 分享卡片

首页另有两个独立入口：**16 型图鉴**（不用测也能看）和**政策速查表**（完整数值 + 文号 + 时效）。

## 分享

结果页卡片下方有分享链接框，链接形如 `https://<站点>/#r=KADC&k=88&a=72&o=61&w=40`，把代号和四维百分比一起编码进 hash：

- 对方打开即直接看到**你的**结果页，四维条、相似/对立人格、金句全部还原
- 顶部有「我也要测 →」入口，点进去是完整答题流程，不会串到你的答案
- 一维复制、二次转发都不丢信息（链接自身可再生成同一条）
- 全程本地计算，链接不含任何个人信息，只有代号和四个百分比

`file://` 双击本地打开时链接无法跨设备使用，页面会直接给出说明而不是生成坏链接；部署到 http(s) 后自动可用。

## 与早期规划稿的差异

实际实现按后续要求做了收窄和调整：

1. **范围收窄**：只做个税综合所得，不含社保、发票、经营所得
2. **无插画**：取消 16 型吉祥物，改为纯字体/CSS 视觉，分享卡片用 Canvas 绘制
3. **尺度放开**：称号改为抽象风格（「税务局查无此人」「12366 接线员已存我号码」「为三块二毛八与系统对线」）
4. **技术选型**：规划稿写的是多文件 + JSON 分离，实际改为**单文件内嵌**——因为 `file://` 协议下 `fetch()` 读本地 JSON 会被 CORS 拦截，单文件才能双击即跑
5. **题量**：规划稿 40 题（12 知识 + 28 情景），实际收窄为 **20 题（5 知识 + 15 情景）**——`Q` 由 `Q_FULL` 按索引筛选而来，全量 40 题保留在源码内未启用
6. **归一化算法改进**：规划稿写的是 `(raw-min)/(max-min)`。实测发现 A/O 维度分值区间不对称（A 为 [-27, +33]），该公式会让中立作答落在 45% 而非 50%，系统性偏向 P/D。已改为：K 维度用 `raw/max`，A/O/W 用 `50 + raw/M×50`（M 取 |min| 与 max 的较大值），使中立点严格对齐 50%。

## 已验证

75 项自动化检查全部通过（两套测试：计分逻辑 52 项 + 全流程 DOM 走查 23 项）：

- 16 型全部可达，随机搜索 30 万次分布 2.5%–10%，无死型
- 极端答卷命中预期（最优 → KAOC，最差 → UPDW）
- 边界型机制会被触发（非死代码）
- 20 题逐题通关、5 道知识题解析均正常弹出、8 道彩蛋均触发
- 分享卡片生成、hash 链接闭环还原、断点续答、非法输入降级
- 政策数值集中在 `POLICY` 常量，知识点出处见各知识题的 `src` 文号字段
- 合规红线：免责声明、12366、96110、政策文号、限时政策截止日期、无违规营销表述

## 改内容时注意

**税务数字改错，项目就从科普变成误导。**

- 所有数值集中在 `index.html` 里的 `POLICY` 常量和 `Q` 数组的知识题解析中
- 改动前先核对各知识题 `src` 字段标注的文号原文
- 两条限时政策（免办汇算 12万/400元口径、年终奖单独计税）**均执行至 2027-12-31**，2028 年起必须重新核实
- 每年 3 月汇算季前建议整体复核一次

## 红线（勿动）

1. 不暗示逃税合理。所有"筹划"严格限定为依法享受扣除，结果页明确区分合法筹划 / 违规填报 / 逃税
2. 恶搞对象只能是行为模式，不能是人群。不拿收入、职业、地域、家庭结构开玩笑
3. 三处免责声明（首页、结果页、分享卡片）不得删除

## 管理员视角与分析模块（2026-11 新增）

首页「管理员视角」入口 → 口令 `lingdao2026` → 匿名测评数据分析。

> **安全提示**：这是纯前端密码门，口令写在页面源码里，**不是真实的安全机制**，只能挡住随手点进来的人。页面内已明确标注这一点。

### 数据流

1. 完成 20 题后进入 5 题问卷（生活状态 + 4 项自述指标），**可跳过**。
2. 提交后写入一条匿名记录到 `localStorage['taxtype_records']`，字段：
   `id / ts / ver（题库版本）/ src（real|sim）/ code / pct / ans（逐题答案）/ kc（答对数）/ kt（知识题总数）/ sv（问卷，可空）/ svSkip`
3. `localStorage['taxtype_starts']` 记录开始次数，用于算完成率。

**不采集任何身份信息**，无网络请求，无第三方模型，无需 API Key。

### 六个分析模块

| 模块 | 内容 | 关键口径 |
|---|---|---|
| ① 知识水平 | 有效答卷数、完成率、平均答对、中位数、答对分布、领域/难度/逐题正确率 | 完成率＝有效答卷÷开始次数（重复开始会拉低，已标注） |
| ② 高频误区 | 误答人次、误答比例、最常见错误选项、关联知识点、教学建议；风险情境判断正确率 | 风险情境判准由题目预设安全选项，非模型判定 |
| ③ 信息素养 | g1–g4 均值与分布、素养指数 | 全部为自述偏好，明确不等同真实行为 |
| ④ 交叉分析 | A 优惠关注×扣除知识；B 知识水平×担忧；C 核验倾向×风险判断 | 阈值：Likert 4–5 高 / 3 中 / 1–2 低；知识 ≥80% 高 / 50–79% 中 / <50% 低；n<5 只作描述 |
| ⑤ 场景比较 | 职场/自由职业/创业者/学生/退休/不愿透露 + 未填问卷，各组知识率与素养均值 | 未选择单列，不推断身份 |
| ⑥ 教育优先级 | 按误答人次排序 Top5 + 建议；一键生成报告；三类 CSV | 报告为 Markdown，可下载/复制 |

### 数据治理

- **实际/模拟分离**：记录带 `src` 字段，管理员页可切换查看；模拟数据可一键写入（40 条）与一键删除。
- **题库版本分离**：记录带 `ver` 字段（当前 `q20-k5`），切版本不合并统计。
- **缺失不补造**：跳过问卷的记录 `sv=null`，只参与知识类分析，不参与偏好/交叉分析。
- **确定性计算**：全部统计由页面内 JS 计算，AI 只可能辅助解读，不修改分数与答案。

### 新增题库元数据

- `META_K`（键＝Q_FULL 下标）：每个知识题的领域 / 难度 / 知识点
- `DOM_ADV`：各领域教学建议
- `META_S`：风险情境题的安全选项下标，用于客观判定

### 已知限制

1. **知识题仅 5 道，覆盖 4 个领域**（扣除条件×2、重复扣除、年度汇算、信息核验）。要求的「收入分类、跨境所得、申报更正」在当前 20 题版本中**未被测到**，报告不外推。题库中其余 9 道知识题（Q_FULL 0、2–5、7、9、12、13）已有元数据，若调整测题组合可自动纳入分析。
2. 风险情境题仅 3 道，覆盖面窄。
3. 自愿样本、非概率抽样、同设备可重复参与，样本不独立。
4. 完成率依赖本机开始计数，清空记录会重置。
5. 本页不评估学习干预效果；前测—后测需另行采集配对样本。

- 情景题：选中即 `next()`，**无任何 setTimeout**

- **占比与排名**：`shareStats(code)` 只统计**当前题库版本 + 实际参与（src=real）** 的记录，输出 `TYPE n/16` 与百分比。样本 N<30 时标注「样本偏小」，N=0 时显示「暂无样本数据」。**不使用任何虚构的全国分布基线。**

结果页新增「你在人群里的位置」卡片，与分享卡使用同一套计算。

## 16 型形象改为马赛克像素风（2026-11 更新）

原先是平滑矢量卡通（ellipse / line / path 曲线）。现整体替换为 **8bit 像素小人**，风格参考游戏属性面板。

### 实现方式

- 字符网格 `PIX_BASE`：**20 × 24**，每格 1 单位
- 字符含义：`K` 描边 / `H` 头部 / `B` 躯干 / `L` 下装 / `S` 鞋
- 五官从 `PIX_EYES`（10 种）、`PIX_MOUTH`（9 种）小图案叠加，按宽度**自动居中**（眼睛关于头部中线 9.5 对称）
- 道具 `PIX_PROP`（13 种）按 `ax/ay` 锚点叠加
- 渲染：同格后写覆盖先写 → 按颜色合并成一条 `<path>` 的 `M{x} {y}h1v1h-1z` 方块指令
- `shape-rendering="crispEdges"` + 整数坐标，缩放后仍锐利
- **不引入任何图片文件**，仍是纯 SVG 字符串，离线可用

### 配色分层（关键修正）

第一版头部与躯干同色，渲染出来糊成一团。现改为三层：

| 部位 | 颜色 |
|---|---|
| 头部（脸） | `c2` 浅色 |
| 躯干（衣服） | `c` 主色 |
| 下装 / 鞋 | `c` 按 0.58 / 0.30 压暗（保留色相） |
| 描边 / 五官 | 近黑 |

压缩色用 `pixShade(hex, f)`，非法输入兜底 `#333333`。

### 分享卡适配

头像区宽高比随 viewBox 改为 **20:24**：

- `AV_W=240, AV_H=288, AV_X=255, AV_Y=408`
- 头像占 **408–696**，上方与占比行（基线 378）留 30px，下方与四维条（730）留 34px，区间内无任何文字

### 其他

- 按要求**未添加「保存图片」按钮**，分享卡仍是「生成分享卡片」后自行截图
- 顺带修正：结果页「14 道知识题全部答对」的错误文案改为按实际题数动态取值

## 修复：分享卡片不显示人格图片（2026-11）

### 根因

`avatar()` 输出的 SVG **缺少 `xmlns` 命名空间声明**。

- 内联在 HTML 里的 `<svg>`：HTML 解析器自动赋予 SVG 命名空间 → 结果页、图鉴显示正常
- 作为 `img.src` 的 data URI 加载：它是**独立的 XML 文档**，没有 `xmlns` 就不是合法 SVG → 浏览器解码失败，canvas 上画不出东西

这个 bug 从最初的平滑矢量版本就存在，两版共用一个错误。

### 为什么之前没测出来

测试里有一条断言写的是 `svg.indexOf('http')<0`，用来"确认无外链"。而正确的 `xmlns="http://www.w3.org/2000/svg"` 恰恰包含 `http`——这条断言把正确写法当成了违规，把 bug 锁死了。

现已改为检查真正的外部资源引用（`<image`、`xlink:href`、`url(http`）。

### 修复内容

1. `avatar()` 根标签加 `xmlns="http://www.w3.org/2000/svg"`
2. `makeCard()` 增加三重保护：
   - URI 编码加载失败 → 自动退回 base64 编码重试一次
   - `onload` 但 `naturalWidth=0`（解码出空图）→ 同样触发重试
   - 3 秒超时保护：`onload`/`onerror` 都不触发时也把卡片画出来，不会永远停在「正在生成卡片…」

### 验证

30 项断言，含：16 型 SVG 全部带 xmlns、URI 与 base64 两种编码解码后与原始 SVG 完全一致、URI 中 `#` 已正确转义、canvas 实际绘制坐标（255/408/240×288）、强制首次加载失败后确实发生 base64 重试且最终画出头像。

## 修复：分享卡「相似/对立人格」文字溢出（2026-11）

### 根因

`drawRel()` 里人格名用固定 `800 30px` 直接 `fillText`，**不换行、不缩放**。

- 卡片框宽 310，左右内边距各 20 → 可用 **270px**
- 30px 中文字宽约 30px → 只能放 **9 个字**
- 但 16 型里有 11 个名字超过 9 字，最长的 `12366 接线员已存我号码` 是 **14 字（约 420px）**

只有描述文字用了 `wrapL` 换行，名字没做任何处理，所以整段挤到框外。

### 修复

新增三个测量驱动的辅助函数：

- `relW(x,t)`：按当前 `x.font` 实测文字宽度
- `fitFont(x,text,maxW,start,min,weight)`：从 30px 递减到 19px，找到单行放得下的字号
- `splitLines(x,txt,maxW,maxLines)`：按实测宽度折行，超过行数上限则截断加 `…`

`drawRel` 改为：

1. 名字先 `fitFont` 缩放；仍放不下再 `splitLines` 折成最多 2 行
2. 描述起始位置按名字实际行数动态下移，剩余高度决定可放行数（1–2 行），超出截断
3. 内部可用宽度再留 **6px 安全边距**，避免真实字体渲染差异导致边缘溢出
4. 框高 146 → **152**，位置 1070 → **1066**（底部 1218，距页脚首行 1258 仍有 40px）

### 两张卡共用字号

相似人格与对立人格并排显示，若各自缩放会出现一个 30px、一个 21px 的失衡。改为先算出两个名字各自的适配字号，**取较小值共用**：

```js
var nsShared=Math.min(fitFont(x,n1,...), fitFont(x,n2,...));
drawRel(..., false, nsShared);
drawRel(..., true,  nsShared);
```

### 实测效果（16 型全量）

改动后所有名字保持 **1 行**，字号自动落在 21–30px：

| 名字长度 | 30px 原始宽度 | 最终字号 |
|---|---|---|
| 4 字（退税の神） | 120px | 30px |
| 7 字（税务局查无此人） | 210px | 30px |
| 11 字 | 316px | 25px |
| 13 字（懂法却怕法·宁可多缴保平安） | 376px | 21px |
| 14 字（12366 接线员已存我号码） | 339px | 23px |

全部 ≤ 264px，在 270px 可用宽度内。
